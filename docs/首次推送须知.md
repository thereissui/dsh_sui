# 第一次把东西推上来之前看这一页

## 一、认证（GitHub token）

这个仓库的 push 用 fine-grained PAT（权限只给这一个仓库）。

**存进本机凭据管理器**（一次即可，之后不用再输）：

```bash
printf "protocol=https\nhost=github.com\nusername=<你的GitHub用户名>\npassword=<你的token>\n\n" | git credential approve
```

或者第一次 push 时让 git 弹框要，输一次就记住（credential helper 已经是 `wincred`）。

**注意**：token **不要**写进任何文件，包括这个仓库里的 md。要临时备份就放 `private/`（那个目录不进 git），用完删掉。

## 二、提交前检查

```bash
git status                                  # 有没有意外改到不该改的
git diff --cached --name-only               # 暂存区里都是什么文件
bash scripts/pre-commit-check.sh            # 自动扫一遍
```

**特别检查**：要在公开仓库里出现的内容里，不能有

- QQ 号、B站 mid、本机绝对路径（形如 `C:\Users\<用户名>\...`）
- 人格卡正文、日记内容
- 任何 token / cookie / 密码

## 三、推

```bash
git push -u origin main
```

如果报 `Failed to connect to github.com:443`，**那是网络问题，不是 token 问题**——重试，或者开代理。

## 四、这个仓库和 surfcore 的关系

`surfcore`（另一台目录下的第三方插件仓库）是另一件事：它是别人开源的仓库，
本地做过大量定制，**不推、不 push**（remote 的 pushurl 被设成 `DISABLED_NO_PUSH`）。

两者的区别：

| | surfcore | dsh_sui（这个） |
|---|---|---|
| 来源 | 别人的仓库 clone | 自己新建 |
| 内容 | 别人的插件 + 我的定制 | 纯我自己的配置与笔记 |
| 能不能推 | ❌ 不能（防手滑） | ✅ 能 |
